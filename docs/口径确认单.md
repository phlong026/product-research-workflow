## 补充假设(研发在实现中额外做出的,同样需要确认)

- **三值判重要求 `monthly_sales>0`、评分∈(0,5]、评分数>0**,避免无评分新品被 0/0/0 合并;评分按解析后的数值精确比较。
- **月份窗口**:默认近 36 个月,最近可得月 = 当前日期往前 1 个月(`available_month_window`)。
- **候选池**:每月取销量降序 Top200 候选,清洗去重后截取 Top100。
- **季节高低月**只在 12 个月齐全的年份判断;缺月年份只给覆盖告警和"待验证假设"。
- **新品窗口**:上架日距抓取月末 ≤90 天为新品;自然月边界,上架当月为第 1 个月。
- **老带新**:同一父体在更早月份已出现即标记排除;人工 `eligible` 标记优先于自动判断。
- **GPT 分类**:低置信/歧义/证据不在原文中/标签越界一律标"待人工",待人工行必须逐一人工指定后才能批准分类检查点。
- **字段别名**:SellerSprite 返回的类目节点、卖家 ID、评分等字段名为推断,**待真实 schema 验证**。

- **多节点月份必须各节点齐全**:某节点缺某月数据时整月不纳入并显式列入缺月(显式月份则直接报错),避免把缺失节点当 0 销量;接口调用失败与"无数据"区分,前者一律报错。
- **新品指标只统计通过新品队列过滤的 ASIN**(上架≤90 天窗口、非老带新、非人工排除);新品表整表无上架时间时无法过滤,显式降级并在资料包"缺失证据"中披露;人工预筛的表可用 `--skip-queue-filter`。
- **表2 的人工地区优先于一切**(含源数据里已有的地区);清空卖点是显式覆盖。表1 的 `sales_rank`/`parent_asin`/`rating`/`rating_count` 为只读列(影响去重/排名,需修改请重新 ingest)。
- **产品迭代进程的"今天"**取数据最大月份的月末(同输入同输出,不随运行日期变化)。
- **规则分类**:多个标签同时命中记为待人工;零命中保留显式的 `unknown`(未归类)类别,前端高亮提示。

- **补齐检查点(表2 人工确认关口)**:商品补齐是独立的 `enrich` 步骤,完成后必须在 `enrichment_review` 人工确认才能分类、分析、出资料包;`import-table --table 2` 保留机器补齐、人工修改优先,并重新请求该检查点;不做补齐且无人工表2 修改时没有此关口。
- **表1/2/3 含义**(研发推荐,待真实业务确认):表1=清洗后月度数据,表2=唯一 ASIN 的地区/卖点(补齐),表3=分类结果。若业务口径中的“表2”指分类表,只需调整表名与顺序。
- **卖家字段名**(待第一次真实联调确认):卖家集中度依赖卖家 ID,当前别名为 `卖家ID/sellerId/seller_id/Seller ID`(推断,未经真实 schema 验证);确认前缺卖家 ID 的 ASIN 不合并、卖家集中度只统计有 ID 的部分并披露覆盖。
- **CSV 防公式注入**:导出的 CSV 对以 `= + - @` 开头的文本加单引号前缀,导入时还原,导出→修改→上传不改变原文。
- **指标对账**:`reconcile` 把已算指标与人工结果逐项对账,缺失/未知判 MISSING 而不是 0,容差必须显式给出,见 `skill/SKILL.md`。
