# T09 专项评审｜New Product Engine + VC

## 范围

- 新品月度快照去重、合并
- 可排除“老带新/不属于真正新品”的记录（`eligible=False`）
- configurable 新品成功标准
- 首次达到销量阈值的月份
- 连续 N 个自然月达到阈值的 `launch_success`
- 当前月仍达到阈值的 `current_survival`
- 成功新品中，在前 N 个月首次跨过阈值的占比
- VC / SC 等 account type 的新品数、成功数、成功率、成功新品占比

## 开源复用

现有 SellerSprite Skill 已有“新品快速爆发”“高新品占比”筛选逻辑和对应 MCP 取数入口，可复用数据获取方式；其 `月销>=300 / 上架<=2个月` 等阈值不适用于本项目通用业务，因此没有复制到核心逻辑。

## 参数化原则

制冰机历史案例使用：

- 月销量阈值：250
- 连续月份：3
- 早期突破观察窗：3个月

这些只应该出现在制冰机项目配置 / Golden Case 中，不是全品类硬编码标准。

## 关键修正

历史资料里“新品成功”和“当前仍存活”容易混在一起，本模块明确拆成：

- `launch_success`：历史上是否曾满足连续 N 个月阈值
- `current_survival`：分析当前月是否仍达到存活阈值

这是对真实案例已有统计口径的代码化，不是新增商业判断。

## 评审结论

- ✅ 缺失自然月会打断连续成功 streak。
- ✅ 重复抓取同一 ASIN/月按最高销量去重。
- ✅ VC/SC 仅作为统计维度，不自动形成“必须 VC”决策。
- ✅ 最终 Yes/No 仍由人工负责。
